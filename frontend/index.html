Data collection

      photos in, training data out

    
The steadiest way to grow a dataset is a
      Telegram bot: photos sent to it land in the project. These are
      the bots of the projects you can open — whether each is alive, who
      may use it, and how to add another.

    
A bot works from day zero. Before the project has a
      trained model it collects: photos go straight to the fix queue,
      unlabeled. Once a run is trained it counts — with the serving
      engine (YOLO always; DEIM when a run of it has been exported). Other
      model families train and compare, but do not answer the bot.

    Add a machine
    
    
    
      
    Add a machine — one command
    
      
    Mint a join command and run it on the GPU machine.
        The box downloads Groundwork from this HQ, installs, configures itself
        as a worker and registers here — cards probed, data plane tested. The
        token inside is single-use and lives 30 minutes.
    
      
    
        
        
      
    
      
    
    
    

    
    
      
    Pair a machine
    
      
    On the new machine: install Groundwork with
        GW_ROLE=worker, open ITS Machines tab, press
        Create pairing code, and paste the string here. One paste
        registers it, exchanges keys and probes its cards. This machine
        will receive full copies of every project you train on it.
    
      
    
        
        
      
    
      
    
    
    

    
    
      
    Pair with an HQ
    
      
    This machine runs as a worker. Mint a one-time
        code and paste it on your HQ's Machines tab. The code contains a
        train-scope API key for this box — treat it like one. Confirm the URL
        first: it is what the HQ will call.
    
      
    
        
        
      
    
      
    
    
    

        
    It needs two things, and they do different jobs.
          The API key is the control plane — probing, dispatching, status

          back, which stays rsync because its incremental delta is why a
          pre-training sync costs a second instead of re-uploading gigabytes.

    API
    
      drive this cockpit from anywhere
    
    
    Everything this interface does, it does over HTTP. The same
      endpoints are yours: start a run on any machine, read what it scored,
      export a model, push images in. Authenticate with an API key as a
      bearer token.
    

    
    
      
    
        
    Getting a key
    
        
    Make one below. It is shown once — the server keeps only a
          SHA-256, so there is no reveal button and there never can be. Revoke it
          any time; anything using it stops immediately.
    
      
    
      
    
        
    Using it
    
        
    Send it as a bearer token, never as a query parameter — URLs end up in
          shell history, proxy logs and screenshots.
    
        
    export GW_KEY=gw_your_key_here
    
      
    
      
    
        
    What a key cannot do
    
        
    Change your password, rename you, manage accounts, or mint another
          key — those need a password session. That asymmetry is what makes a key
          safe to leave in a config file on a training box: if it leaks you
          revoke it, you do not lose the account.

    What is Groundwork?
    
        
    Groundwork teaches a computer to count things in
          photographs. You show it examples, mark what you want counted, and it
          learns to do it for you.
    
        
    What you end up with is a trained detector — a file
          that runs wherever you put it: a chat bot, this cockpit, a phone, a
          Raspberry Pi with a camera over a bench. It is a workshop, not one
          tool: each thing you teach it to see is a project.
          a bolt counter, a seed counter and a rivet counter are three projects,
          not three installs. A fresh instance starts empty — the setup wizard
          walks you into your first one.
